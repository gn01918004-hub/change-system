# 土地重測資料轉換系統

目前版本見 [`version.json`](version.json)，更新內容見 [CHANGELOG.md](CHANGELOG.md)。

把外業儀器（全站儀、GPS 控制器）和**土地重測系統**之間的資料轉換，整合成一個介面。

## 怎麼用（三步驟）

1. 用 Chrome 或 Edge 打開 **`dist/土地重測資料轉換系統.html`**（雙擊就可以，不用安裝、不用網路）。
2. 把檔案拖進畫面，系統會自己認出是哪一種檔案；也可以按 **📁 選擇整個資料夾**（或直接把資料夾拖進來），系統會自動找出裡面可以轉換的檔案讓你勾選。
3. 看**點位縮圖**和紅色、黃色的提醒，然後按綠色的 **⬇ 下載**。要改檔名就直接點檔名。

所有轉換都在自己的電腦上完成，檔案不會上傳到任何地方。

**存檔位置**：下載按鈕旁邊（或右上角）的「📁 選擇存檔資料夾」可以選一次資料夾（建議選系統所在的資料夾），之後按下載都會直接存進去，不用再到「下載」資料夾找。**自動切換**：用「📁 選擇整個資料夾」讀檔，或把資料夾拖進來時，那個資料夾就會自動設成存檔位置（所有功能都一樣，包括輸出航照圖），不會一直沿用上次的資料夾。每份複製到不同位置的系統會各自記住自己的資料夾；同名檔案已存在時自動加上 (1)、(2)，不會蓋掉。重新打開時瀏覽器可能會問一次「允許編輯檔案」，按允許即可（需要 Chrome 或 Edge）。

| 功能 | 放入 | 得到 | 取代的舊工具 |
|---|---|---|---|
| 全站儀 → 重測系統 | Nikon `.RAW` | `.mac`（後視不為 0 時另外產生 `_Zero.mac`） | RawToMACV2.0.jar、NIKON轉MAC 0714F5.xls |
| GPS → 重測系統 | 控制器輸出的 `.CSV` | `.cnt`（點號.編碼,Y,X）＋ `_整理.csv`（＋ 有改編碼時的 `_編碼對照表.csv`）；有 D14、D20 時直接寫入 | CSV TO 重測 CT02.xls |
| 重測 → 全站儀 / GPS 控制器 | `.L02` `.L14` `.L20` | `.csv` 或 `.txt`（點號,Y,X），兩種儀器用同一個檔 | 重測轉CSV TS01.xls、TrimblePointInputV3.jar |
| 複丈輸入檔 → 全站儀 / GPS 控制器 | `.COA` `.CTL` `.BNP` `.PAR`（同名） | 同上（點號,Y,X） | 複丈輸入檔2SOKKIA v3.1.exe |

`samples/` 資料夾裡有範例檔，可以拖進去試試看。

## 新功能

### 點位縮圖
每次轉換都會畫出點位分布的小縮圖，點一下可以放大，滑鼠移到點上會顯示點名。
* **GPS**：藍點是要轉換的點，橘點是要轉換但有疑慮的點，紅圈是剔除的點，綠色三角形是虛擬測站和後視點。放大圖裡**點一下點位就能切換「轉換／剔除」**。
* **全站儀**：用 RAW 檔裡的已知坐標（UP 紀錄）推算測站和觀測點的大略位置，並畫出觀測方向線。
* **重測資料**：紅色三角形是控制點（L02），藍點是界址點／參考點（L14），綠點是補點（L20）。

### GPS 原始檔自動整理與點位檢查
控制器直接輸出的 CSV（`點名,N,E,高程,編碼`，裡面混有現場核對點和雜點）會先自動整理成 `點名,N,E,編碼` 再轉換，也會另外輸出一份 `_整理.csv` 留存。拿實際的 `20250722` 原始檔測試，整理結果和手動整理的檔案逐字相同。

每一點都列在「點位檢查」表裡，可以勾選要轉換或剔除：

| 狀況 | 判斷方式 | 預設 |
|---|---|---|
| 雜點 | 坐標是 0 或不是數字 | 剔除 |
| 現場核對點 | 沒有編碼，而且高程是 0（或沒有高程欄時點名不是數字） | 剔除 |
| 離其他點太遠 | 與點群中心的距離大於一般距離的 10 倍（至少 200 m） | 剔除 |
| 點名重複 | 保留第一筆 | 剔除後面那筆 |
| 補點 | 點名 **Q 開頭且有高程**（例如 QGGC32），或數字點號的**編碼寫 Q 開頭**（編碼就是補點名稱：`13,…,q11` → `Q11`；編碼只有字母時接上點號：`12,…,QW` → `QW12`） | 轉換；有放 D20 時寫進補點檔 |
| 系統原有的 Q 點 | 點名 Q 開頭但**沒有高程**（例如 QW1） | 剔除（當現場核對點） |
| 現場收的點 | 沒有編碼但**有高程** | 轉換，但**要你決定編成幾號**（00～99），回答前不給下載 |
| 編碼不是 00～99 | 例如 `be73`、`q11`、`123` | 轉換，**自動改成 11**（進階設定可改號碼），列入編碼對照表 |
| 坐標和其他點相同 | — | 轉換，但標黃色提醒 |

**編碼對照表**（`_編碼對照表.csv`）：有點的編碼被改過時會產生，列出每一點的原點名、原編碼、寫進重測系統的點號、坐標與說明，可直接用 Excel 開啟或列印。點位檢查表的「寫入編碼」欄也可以個別修改。

**N、E 順序自動檢查**：台灣 TWD97 的 N（約 2,700,000）一定比 E（約 200,000）大很多。如果控制器輸出成「點名,E,N」，系統會自動對調並以黃色提醒。「進階設定」也可以強制指定。

### 重測資料匯出（全站儀、GPS 控制器共用）
全站儀和 GPS 控制器吃的格式完全相同（`點號,Y,X`，逗號分隔），所以一個案件只輸出**一個檔**，兩種儀器都用它。點位順序一律是**界址點／參考點 → 補點 → 控制點**。

存檔區上方可以選**坐標順序** `Y , X`（預設）或 `X , Y`，系統會記住，並顯示第一點當例子。系統會**依位數自動判斷原檔哪個是 Y**：**Y 的整數部分一定是 7 位數**（常見 27… 開頭）、**X 一定是 6 位數**（常見 21… 開頭），所以原檔就算 X 在前或混在一起也會排對，並提醒調整了幾點；看不出來的（例如假設坐標）照原順序並提醒。

存檔區上方可以選副檔名 **.csv**（預設）或 **.txt**，兩種內容完全一樣，只差副檔名，給只認 `.txt` 的儀器用。系統會記住你的選擇。
注意：`.csv` 用 Excel 打開再存檔，可能把 `2707967.750` 改成 `2707967.75`，所以只看不要存。

### 複丈輸入檔（資料夾沒有 L02/L14/L20 時使用）
* 讀同名的 `.COA`（界址點坐標）、`.CTL`（控制點）、`.BNP`（地號的界址點）、`.PAR`（地號清單）；`.D20` 用不到。
* 資料夾裡**沒有** L02/L14/L20 時，選資料夾會自動列出；有的話預設不列，要用時點首頁「匯出」區的**「複丈輸入檔 → 全站儀 / GPS 控制器」**卡片。
* 預設全部轉出（全部控制點＋全部界址點）。第 2 步可以：
  * **指定地號**：直接輸入（`12 15-1 20~25`，`~` 表示範圍）或在清單搜尋勾選；
  * **控制點**：全部／**每筆地號最近的點**（預設 2 點，一組測站＋後視，可改）／不要；
  * **手動加減控制點**：輸入 `BKC001 BKC161~BKC170` 或在清單勾選，滑鼠移到點名上可看為什麼被選；
  * **排序**：一律界址點在前、控制點在後。
* 檔案格式（已用實際檔案核對）：`.COA` 每行「點號(5) 空白 Y(16) X(15) 註記(1)」，`.CTL` 每行「點名(8) Y(11) X(10) 註記(1)」。Y、X 是黏在一起的，依固定欄寬切開；最後一碼是註記，不是坐標的一部分（舊程式也不輸出它）。

### 輸出格式（重測資料、複丈輸入檔共用）
| 格式 | 內容 | 說明 |
|---|---|---|
| 通用 CSV（預設） | `點號,Y,X` | 副檔名 .csv/.txt、坐標順序 Y,X/X,Y 可選 |
| SOKKIA .sdr | SDR33：`00NM`、`10NM` 標頭＋每點 `08KI` 一行 | 和舊程式逐字相同 |
| TOPCON .txt | `點號,Y,X,0.000,1` | 和舊程式逐字相同 |

有指定地號時檔名會加上地號（例如 `KC1117` ＋地號 1、2、3 → `KC11171_2_3.sdr`），和舊程式一樣。

### 直接寫入重測系統檔（.D14 參考點／.D20 補點）
把 **GPS 的 CSV** 或 **全站儀的 RAW** 和重測系統的 **.D14、.D20 一起**放進來（或選整個資料夾），**第 3 步就變成「寫入重測系統」**（主力），舊的 CNT＋MAC 檔收起來、需要時按「展開」。沒有放 D14、D20 時跟以前一樣只做 CNT＋MAC。

兩種輸出用的是同一份點位檢查，只是規則不同：

| 例子 | 直接寫入 | CNT（不能有 Q 點） |
|---|---|---|
| `13,…,q11`（編碼 Q 開頭） | 補點 **Q11** → D20 | **13.11** |
| `QGGC32,…,97.082`（Q 開頭、有高程） | 補點 **QGGC32** → D20 | 自動編成參考點 **42.11**（這批最大點號＋1） |
| `2,…,30` | 參考點 **2.30** → D14 | 2.30 |

* **寫到哪裡**：點名 **Q 開頭**（例如 QW4、QT60-2）→ `.D20` 補點（等級 Q）；**數字點號** → `.D14` 參考點，點號＋編碼（例如 1.32），`COT_SOURCE` 寫 2（計算求得）。其他點名（例如 BE73）不能寫入，會標示出來。
* **點號重複**：`.D14` 裡同一點號可以有不同編碼（5 號界址點 5.00 和 5 號參考點 5.30 不衝突），點號＋編碼都一樣才算重複。重複時自動改成該編碼目前最大號＋1；補點名稱重複時尾數＋1（QW3 → QW4）。表格裡可以直接改點號、編碼，或取消勾選不寫入。
* **缺編碼**：沒有編碼的點要先在表格填編碼（00～99）才能寫入。
* **參考點點號**：新點的點號只要和 D14 裡任何參考點（X.XX；計算求得的 X.00 不算）重複，就改成**參考點最大號＋1**，改號也會套用到 MAC／CNT（例如 1～14 → 26～39）。
* **6 cm 內的重測點**：同點號或同補點名稱、坐標相差 6 cm 內視為同一點重測，**預設不寫入**並列出差值；打勾可改寫成新的參考點（X.XX，補點預設編碼 11）。相差超過 6 cm 視為不同點，照上面的規則改號。
* **全站儀 MAC 格式**：預設和 Excel 轉檔工具存出來的一樣（Tab 分隔、去尾 0、數字點號後加空白、Q 點照原名，例如 `26.20 \t\t210.4943\t\t90.2904\t\t82.403`），進階設定可改回空白分隔。
* **全站儀 RAW**：用 `.D14`、`.D20` 和 RAW 檔裡 UP 紀錄的已知坐標，依測站、後視算出每個新點的坐標；照準已知點的檢核觀測不會重複寫入。
* **存檔**：「💾 直接寫入原檔」會請你選重測系統放 D14、D20 的資料夾，確認裡面的檔案和放進來的一樣後，**先把原檔備份成 `.bak`**（已有備份就加上日期時間），再寫入新檔。也可以「下載新的 D14 / D20」自己取代，或「下載對照表」。
* 寫入時只在檔案尾端加上新紀錄並更新筆數與日期，原有的紀錄一個位元組都不會動。用實際的 KC1114 檔核對過：寫出來的格式和重測系統自己寫的完全相同。

### 輸出航照圖（JPG + JGW，可校正偏差）

首頁「其他 → 輸出航照圖」，或選資料夾讀到 L02／L14／L20 時，清單下方的「其他：輸出航照圖」。依案件點位自動到國土測繪中心 WMTS 抓正射影像，存成 `案件_航照.jpg` + `案件_航照.jgw`（TWD97 TM2，6 行世界檔，CRLF），CAD／GIS 直接疊圖。需要網路。

1. **範圍**：L14／L20 點位（有其他點時不算 L02 控制點）分群，取點最多的一群為中心，離很遠的零星點不算（可勾「全部算進去」）；四周外擴 30 m，邊長至少 200 m。
2. **圖源**：
   - 正射影像圖(通用)_3826（`https://wmts.nlsc.gov.tw/97/wmts`，TWD97 原生，0.26 m，建議）
   - 正射影像圖(通用)（Web Mercator 第 20 層，約 0.14 m，較新；在瀏覽器內轉投影到 TWD97）
   - 兩個是不同年份的航照，偏差不一定一樣。
3. **偏差校正**（實測 − 航照，取平均）：
   - 套合點：先輸出一次 → 「🎯 選套合點」→ 點實測點（黃＝本次點位、灰＝D14 參考點）→ 點航照上它真正的位置。滾輪放大、拖曳移動，即時預覽校正結果；「和平均差」大的可取消或刪除。
   - D14 裡有指定編碼（預設 87）的航照判讀點時，自動配對 10 m 內最近的實測點，也列進套合點。
   - 也可以直接輸入 N／E 位移（每個圖源分別記住）。
4. **輸出**：「套用並重新輸出」後下載 JPG + JGW。範圍太大（超過約 2500 萬像素）時自動降低解析度。

### 拖放
檔案或整個資料夾可以拖到視窗的任何地方，畫面會出現「放開滑鼠」的提示。

### 選資料夾
* 同一個資料夾、同一個主檔名的 `.L02`（控制點）、`.L14`（界址點、參考點）、`.L20`（補點）視為**同一個案件，合併成一個檔**。
* 資料夾裡有好幾個案件、RAW 或 CSV 時，會列出清單讓你勾選要轉哪些；每個案件各自產生一個檔。
* **KC0000.L02** 是每個資料夾都有的系統預設檔，選資料夾時會自動略過；除非路徑裡有名為 KC0000 的資料夾。
* 有重測資料時，可以勾選**要匯入哪幾種資料**（控制點 L02、界址點/參考點 L14、補點 L20），預設全選，資料太多時可以只轉需要的。轉換畫面上方也可以隨時再勾選。

## 和舊工具比較：保留了什麼、修正了什麼

### 全站儀 RAW → MAC
* **保留**：jar 版的 `_Zero.mac` 後視歸零功能，以及 Excel 版的「點號.編碼」和自由測站（RE）提示。
* **修正**：
  * jar 版的歸零永遠不會觸發，因為比對點號時把編碼也算進去了（`102.0` ≠ `102`），所以 `_Zero.mac` 其實和原檔一樣。現在改成用 F1 後視觀測（或照準後視點的 SS 觀測）當歸零基準。
  * jar 版只會歸零「後視之後」的觀測，現在整站都會歸零。
  * jar 版沒有編碼欄時，會把**觀測時間**當成編碼。
  * jar 版的角度會出現 `xx.xx60`（60 秒沒進位）。
  * jar 版遇到空白行會當掉；Excel 版最多只能處理 300 行，還要手動複製貼上到記事本。
  * 新增檢查：儀器角度單位不是度分秒、距離單位不是公尺、編碼不是數字、點號重複。

### GPS CSV → CNT + MAC
* **保留**：Excel 版的方法（第 1 點當虛擬測站 99999、第 2 點當後視 99998，用方位角差和水平距離寫成 MAC）。
* **修正**：
  * 正北／正南方向的公式錯誤（會回傳弧度 1.57，不是 180°）。
  * 第 2 點和第 1 點重合時整批算錯，現在會自動改用下一個不重合的點當後視。
  * 新增**反算檢核**：用寫進檔案的角度、距離把坐標推回來，顯示最大誤差（mm）。
  * 會自動略過標題列，點名和 99999／99998 衝突時會警告。

### 重測資料 → 全站儀 / GPS
兩個舊工具輸出的格式其實一樣（`點號,Y,X`），差別在讀檔方式：
* TS01.xls 每行只讀**第一個點**，而且每種檔案最多 825 點。
* TrimblePointInputV3.jar 每行讀全部的點，但會把 `12.05` 這種點號直接截成 `12`，而且只抓執行目錄下的檔案、固定輸出成 `out.txt`。

新版本每行讀全部的點，標題和頁碼行會自動跳過；只會去掉 `.00` 這種全是 0 的小數，要不要去掉編碼可以在設定裡選；完全相同的重複點只保留一筆，坐標不同的重複點會警告。

## 需要確認的設定（在「進階設定」裡）

* **點號編碼格式**：Excel 版補成兩位（1001.05），jar 版照原樣（1001.5）。預設用 Excel 版的補兩位。
* **角度秒數小數位**（GPS → MAC）：預設整數秒（和 Excel 版一樣）。
* **欄位分隔**：預設空白（jar 版），也可以改成 Tab（Excel 版）。

## 版本與更新提醒

* 右上角的版本號（例如 `v1.3.0`）點一下可以看**更新歷程**，也可以手動「檢查有沒有新版本」。
* 每次打開網頁時，會到 GitHub 讀取這個專案的 `version.json`。有新版本時，畫面上方會出現提醒，按「⬇ 下載新版」就會下載新的 HTML，用它取代舊檔即可。
* 沒有網路時會安靜略過，不影響使用。按「這版先不要」，同一個版本就不會再提醒。

### 發布新版本的步驟（給維護的人）

1. 修改 `version.json`：把 `version` 加一（修錯誤改第三碼，加功能改第二碼），並在 `changelog` 最上面加一筆更新內容。
2. 執行 `npm run build`，網頁和 `CHANGELOG.md` 會一起更新。
3. commit 並 push 到 GitHub 的預設分支，大家下次打開舊版時就會看到提醒。

## 開發

```bash
npm test        # 測試轉換核心
npm run build   # src/core.js + src/app.html → dist/土地重測資料轉換系統.html
```

* `src/core.js`：轉換邏輯，瀏覽器和 Node 都能用
* `src/app.html`：介面
* `dist/`：打包好的單一 HTML 檔，直接發給大家用就好
