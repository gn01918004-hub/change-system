# 土地重測資料轉換系統

把外業儀器（全站儀、GPS 控制器）和**土地重測系統**之間的資料轉換，整合成一個介面。

## 怎麼用（三步驟）

1. 用 Chrome 或 Edge 打開 **`dist/土地重測資料轉換系統.html`**（雙擊就可以，不用安裝、不用網路）。
2. 把檔案拖進畫面，系統會自己認出是哪一種檔案；也可以按 **📁 選擇整個資料夾**（或直接把資料夾拖進來），系統會自動找出裡面可以轉換的檔案讓你勾選。
3. 看**點位縮圖**和紅色、黃色的提醒，然後按綠色的 **⬇ 下載**。

所有轉換都在自己的電腦上完成，檔案不會上傳到任何地方。

| 功能 | 放入 | 得到 | 取代的舊工具 |
|---|---|---|---|
| 全站儀 → 重測系統 | Nikon `.RAW` | `.mac`（後視不為 0 時另外產生 `_Zero.mac`） | RawToMACV2.0.jar、NIKON轉MAC 0714F5.xls |
| GPS → 重測系統 | 控制器輸出的 `.CSV` | `.cnt` ＋ `.mac` ＋ `_整理.csv` | CSV TO 重測 CT02.xls |
| 重測 → 全站儀 | `.L02` `.L14` `.L20` | `.CSV`（點號,Y,X） | 重測轉CSV TS01.xls |
| 重測 → GPS 控制器 | `.L02` `.L14` `.L20` | `.csv`（點號,Y,X） | TrimblePointInputV3.jar |

`samples/` 資料夾裡有範例檔，可以拖進去試試看。

## 新功能

### 點位縮圖
每次轉換都會畫出點位分布的小縮圖，點一下可以放大，滑鼠移到點上會顯示點名。
* **GPS**：藍點是要轉換的點，橘點是要轉換但有疑慮的點，紅圈是剔除的點，綠色三角形是虛擬測站和後視點。放大圖裡**點一下點位就能切換「轉換／剔除」**。
* **全站儀**：用 RAW 檔裡的已知坐標（UP 紀錄）推算測站和觀測點的大略位置，並畫出觀測方向線。
* **重測資料**：紅色三角形是控制點（L02），藍點是界址點／參考點（L14），綠點是補點（L20）。

### GPS 原始檔自動整理與點位檢查
控制器直接輸出的 CSV（`點名,N,E,高程,編碼`，裡面混有現場核對點和雜點）會先自動整理成 `點名,N,E,編碼` 再轉換，也會另外輸出一份 `_整理.csv` 留存。拿實際的 `20250722` 原始檔測試，整理結果和手動整理的檔案逐字相同。

每一點都列在「點位檢查」表裡，可以勾選要轉換或剔除：

| 狀況 | 判斷方式 | 預設 |
|---|---|---|
| 雜點 | 坐標是 0 或不是數字 | 剔除 |
| 現場核對點 | 沒有編碼，而且點名不是數字或高程是 0 | 剔除 |
| 離其他點太遠 | 與點群中心的距離大於一般距離的 10 倍（至少 200 m） | 剔除 |
| 點名重複 | 保留第一筆 | 剔除後面那筆 |
| 沒有編碼、編碼不是數字、坐標和其他點相同 | — | 轉換，但標黃色提醒 |

### 選資料夾
* 同一個資料夾、同一個主檔名的 `.L02`（控制點）、`.L14`（界址點、參考點）、`.L20`（補點）視為**同一個案件，合併成一個檔**。
* 資料夾裡有好幾個案件、RAW 或 CSV 時，會列出清單讓你勾選要轉哪些；每個案件各自產生一個檔。

## 和舊工具比較：保留了什麼、修正了什麼

### 全站儀 RAW → MAC
* **保留**：jar 版的 `_Zero.mac` 後視歸零功能，以及 Excel 版的「點號.編碼」和自由測站（RE）提示。
* **修正**：
  * jar 版的歸零永遠不會觸發，因為比對點號時把編碼也算進去了（`102.0` ≠ `102`），所以 `_Zero.mac` 其實和原檔一樣。現在改成用 F1 後視觀測（或照準後視點的 SS 觀測）當歸零基準。
  * jar 版只會歸零「後視之後」的觀測，現在整站都會歸零。
  * jar 版沒有編碼欄時，會把**觀測時間**當成編碼。
  * jar 版的角度會出現 `xx.xx60`（60 秒沒進位）。
  * jar 版遇到空白行會當掉；Excel 版最多只能處理 300 行，還要手動複製貼上到記事本。
  * 新增檢查：儀器角度單位不是度分秒、距離單位不是公尺、編碼不是數字、點號重複。

### GPS CSV → CNT + MAC
* **保留**：Excel 版的方法（第 1 點當虛擬測站 99999、第 2 點當後視 99998，用方位角差和水平距離寫成 MAC）。
* **修正**：
  * 正北／正南方向的公式錯誤（會回傳弧度 1.57，不是 180°）。
  * 第 2 點和第 1 點重合時整批算錯，現在會自動改用下一個不重合的點當後視。
  * 新增**反算檢核**：用寫進檔案的角度、距離把坐標推回來，顯示最大誤差（mm）。
  * 會自動略過標題列，點名和 99999／99998 衝突時會警告。

### 重測資料 → 全站儀 / GPS
兩個舊工具輸出的格式其實一樣（`點號,Y,X`），差別在讀檔方式：
* TS01.xls 每行只讀**第一個點**，而且每種檔案最多 825 點。
* TrimblePointInputV3.jar 每行讀全部的點，但會把 `12.05` 這種點號直接截成 `12`，而且只抓執行目錄下的檔案、固定輸出成 `out.txt`。

新版本每行讀全部的點，標題和頁碼行會自動跳過；只會去掉 `.00` 這種全是 0 的小數，要不要去掉編碼可以在設定裡選；完全相同的重複點只保留一筆，坐標不同的重複點會警告。

## 需要確認的設定（在「進階設定」裡）

* **點號編碼格式**：Excel 版補成兩位（1001.05），jar 版照原樣（1001.5）。預設用 Excel 版的補兩位。
* **角度秒數小數位**（GPS → MAC）：預設整數秒（和 Excel 版一樣）。
* **欄位分隔**：預設空白（jar 版），也可以改成 Tab（Excel 版）。

## 開發

```bash
npm test        # 測試轉換核心
npm run build   # src/core.js + src/app.html → dist/土地重測資料轉換系統.html
```

* `src/core.js`：轉換邏輯，瀏覽器和 Node 都能用
* `src/app.html`：介面
* `dist/`：打包好的單一 HTML 檔，直接發給大家用就好
